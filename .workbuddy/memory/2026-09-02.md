### 新增文件（lib/ 逻辑层 + app/ API 层 + 组件 + 测试）
- `lib/delivery-types.ts` — 核心类型：`TaskDelivery`/`DeliveryAttempt`（不可变）/`DeliverySnapshot`/`CommandRun`/`VerificationAggregate`/`DeliveryMergeResult`/`DeliveryMergeRejectReason` 等
- `lib/delivery-state.ts` — 状态机纯函数（无 IO）：`TRANSITIONS` 表 + `canTransition`/`assertTransition`/`aggregateVerification`/`resolveVerificationStatus`/`canAccept`/`isSnapshotStale`/`TERMINAL_STATUSES`

- `app/api/deliveries/route.ts` — `GET /api/deliveries?sessionId=`

- `components/DeliveryReview.tsx` — 最小证据展示（变更文件/验证状态/命令记录/不可合并原因/接受/丢弃/验证）

### 关键实现要点
- 状态机：running/verifying/ready_for_review/verification_failed/unverified/cancelled/accepted/discarded；required 全过→ready_for_review，任一 required 失败→verification_failed，零 required→unverified
- 验证快照：进 verifying 时用 `GIT_INDEX_FILE=<tmp>` + read-tree/add -A/write-tree/commit-tree 物化 immutable delivery commit，不改写用户 worktree
- 合并 CAS：`git update-ref <refs/heads/branch> <mergeCommit> <verifiedBaseHeadSha>`，precondition 失败即拒绝；`snapshot_stale` 永不可接受
- **changedPaths 改为服务端 `listChangedPaths` 推导**（本次收尾：`transitionToVerifying` 去掉客户端参数，符合「不信任客户端路径」原则）
